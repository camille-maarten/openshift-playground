# Release Notes - Version 0.0.1

**Release Date**: November 17, 2025
**Status**: Initial Release

## Overview

This is the initial release of the OpenShift Playground, providing an automated installation and configuration solution for Red Hat OpenShift GitOps (ArgoCD) and Gitea Git server on OpenShift clusters.

## Features

### ArgoCD Installation & Configuration

- **Automated ArgoCD Deployment**
  - Installs Red Hat OpenShift GitOps Operator
  - Deploys ArgoCD instance with production-ready configuration
  - Configures high availability options and resource limits
  - Sets up OpenShift routes with TLS termination

- **Multi-User Authentication**
  - Default admin account with password: `argocd1234!!`
  - Local admin-user account with password: `argocd1234!`
  - OpenShift OAuth integration (recommended)
  - Properly configured RBAC policies for admin and developer roles

- **ArgoCD Configuration**
  - Pre-configured ConfigMaps for ArgoCD settings
  - RBAC policies with role-based access control
  - Repository credentials management
  - Resource customizations for OpenShift-specific resources
  - Application reconciliation timeout settings
  - Kustomize and Helm support enabled

### Gitea Git Server

- **Self-Hosted Git Solution**
  - Automated Gitea deployment via Helm
  - SQLite database for lightweight operation
  - OpenShift route configuration with TLS
  - Default admin credentials: `admin` / `gitea1234!`
  - SSH and HTTP/HTTPS Git access

- **OpenShift Integration**
  - Proper security context constraints (SCC) configuration
  - Persistent volume claims for data storage
  - Service and route configuration for external access

### Installation Script

- **Interactive Installation Wizard**
  - Step-by-step installation process
  - Component selection (ArgoCD only, ArgoCD + Gitea, ArgoCD + GitHub)
  - Automatic verification of prerequisites
  - Progress indicators and status updates
  - Comprehensive error handling

- **Post-Installation Information**
  - Environment configuration markdown files
  - Access credentials summary
  - Quick reference guides
  - ArgoCD CLI login commands
  - Next steps and usage instructions

### Manifest Files

- **Namespace & Operator Setup**
  - `01-namespace.yaml` - OpenShift GitOps namespace
  - `02-operatorgroup.yaml` - Operator group configuration
  - `03-subscription.yaml` - GitOps operator subscription

- **ArgoCD Configuration**
  - `04-argocd-instance.yaml` - ArgoCD custom resource with extraConfig for local users
  - `05-argocd-repositories-configmap.yaml` - Repository credentials template
  - `06-argocd-cm-configmap.yaml` - ArgoCD general configuration (reference only, managed by operator)
  - `07-argocd-rbac-configmap.yaml` - RBAC policies and role assignments
  - `10-admin-password-secret.yaml` - Admin and admin-user passwords

## Technical Details

### ArgoCD Configuration

**User Accounts**:
- `admin` - Default administrator account (password: `argocd1234!!`)
- `admin-user` - Local administrator account (password: `argocd1234!`)
- Both accounts have full admin privileges via RBAC

**RBAC Policies**:
- `role:admin` - Full access to all ArgoCD resources
- `role:developer` - Application management capabilities
- `role:readonly` - Read-only access (default for all users)

**Resource Limits**:
- Server: 250m-500m CPU, 256Mi-512Mi memory
- Controller: 500m-2 CPU, 1Gi-2Gi memory
- Repo Server: 250m-1 CPU, 512Mi-1Gi memory
- Redis: 250m-500m CPU, 256Mi-512Mi memory

### Gitea Configuration

**Deployment**:
- Helm chart from official Gitea repository
- SQLite database for simplicity
- OpenShift anyuid SCC for compatibility

**Access**:
- HTTP/HTTPS via OpenShift route
- SSH access on port 22
- Admin user pre-configured with default credentials

## Important Notes

1. **Password Management**: The admin-user account is configured via the ArgoCD CR's `extraConfig` field. The password is stored as a bcrypt hash in the `argocd-secret`.

2. **ConfigMap Management**: The `argocd-cm` ConfigMap is managed by the ArgoCD operator. Local user accounts must be defined in the ArgoCD CR's `extraConfig` section, not by manually applying the ConfigMap.

3. **Security**: Default passwords are provided for convenience in development/demo environments. Change these passwords for production use:
   ```bash
   # Generate new bcrypt hash
   htpasswd -nbBC 10 "" your-password | tr -d ':\n' | sed 's/$2y/$2a/'
   ```

4. **OpenShift OAuth**: For production environments, it's recommended to use OpenShift OAuth integration for authentication rather than local user accounts.

## Architecture

### Component Flow
```
OpenShift Cluster
├── openshift-gitops namespace
│   ├── ArgoCD Operator (installed)
│   ├── ArgoCD Instance (deployed)
│   ├── ConfigMaps (argocd-cm, argocd-rbac-cm, argocd-repositories)
│   ├── Secrets (argocd-secret with passwords)
│   └── Routes (openshift-gitops-server)
└── gitea namespace (optional)
    ├── Gitea Deployment (via Helm)
    ├── PostgreSQL/SQLite (database)
    ├── PVC (persistent storage)
    └── Routes (gitea-http)
```

### Authentication Flow
1. User accesses ArgoCD route URL
2. Login options:
   - OpenShift OAuth (redirects to OpenShift login)
   - Local user (admin or admin-user with password)
3. RBAC policies evaluated based on user/group
4. User granted access per role assignments
